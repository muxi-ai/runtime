## Overview

This PRD outlines two projects to introduce secure sandboxed code execution within MUXI:

1. **RCE (Remote Code Execution)** - Stateless execution of code using a shared sandbox container.
2. **Sandbox (Persistent)** - Long-lived containers for autonomous agents with persistent workspaces.

The goal is to enable agents to execute code safely and predictably, whether as isolated code snippets or through full-scale autonomous development environments.

---

## Problem Statement

Agents in MUXI often need to write and execute code as part of their workflows. Direct execution within the agent process is unsafe, and spinning up containers ad hoc is slow and resource-intensive. These two initiatives define structured, modular, and secure mechanisms to support:

1. One-off stateless execution of code snippets (RCE).
2. Persistent, autonomous containers for long-running agents with full control over their environment (Sandbox).

---

## Goals

* Provide a standard mechanism for executing code generated by agents.
* Ensure sandboxing is always enforced server-side.
* Allow for safe, auditable, and modular code execution.
* Support both lightweight use cases and full autonomy for dev agents.

## Project 1: RCE (Remote Code Execution)

### Description

The RCE project introduces a mandatory MCP service (`mcp/rce`) responsible for handling one-off code execution. Code is executed within a shared sandbox container that supports multiple languages and is pre-loaded with standard developer tools.

### Components

* **`mcp/rce`**: Local command invoked by the MUXI Server.
* **Unified Docker container** (`muxi/rce-runner`):

  * Based on Ubuntu, preinstalled with Python, Node.js, PHP, Bash, etc.
  * Mounted with shared volumes for job communication.
  * Exposes an internal `/run` endpoint.
* **Job directory structure**:

  * `/rce/job-<id>/text.py`
  * `/rce/job-<id>/result.json`
  * `/rce/job-<id>/artifacts/` (optional output files)

### Agent Usage Example

```json
{
  "tool": "rce",
  "input": {
    "language": "python",
    "code": "print('Hello, world!')"
  }
}
```

### Artifact Handling

* Executed code may generate output files (e.g., `.md`, `.png`, `.docx`).
* The sandbox container writes them to `/rce/job-<id>/artifacts/`.
* The MCP returns metadata for each artifact:

```json
{
  "artifacts": [
    {
      "name": "chart.png",
      "path": "artifacts/chart.png",
      "mime": "image/png",
      "size": 34512,
      "url": "/rce/job-abc123/artifacts/chart.png"
    }
  ]
}
```

* Files can be returned inline, served via a static route, or exposed with a `/download` endpoint.

### Mandatory Nature

* The `mcp/rce` service is **mandatory** and **automatically injected by the MUXI Server**.
* The **Overlord system message** instructs all agents to use this service for code execution.
* For **MUXI Runtime users**, manual configuration is required to self-host the MCP.

### Infrastructure Notes

* No cold starts: the sandbox container runs continuously.
* Clean, reusable execution space per job ID.
* Secure and resource-bounded via Docker config.

## Project 2: Sandbox (Persistent)

### Description

Advanced autonomous agents require a persistent execution environment, complete file system access, shell execution, and the ability to run long-lived dev loops. In this project, agents can be launched as independent containers with full system control and exposed over A2A.

### Characteristics

* Agent runs in its own Docker container.
* Overlord discovers the agent via A2A.
* Agent exposes HTTP endpoints for orchestration.
* Optional persistent workspace mount.
* MUXI does not enforce SDK use; agent controls its logic internally.

### Formation example

```yaml
agents:
  - name: devops-agent
    persistent: true
    docker_compose: ./devops-agent.yaml
```

### Docker Compose example

```yaml
services:
  devops-agent:
    image: muxi/agent-devops:latest
    ports:
      - "4100:4100"
    volumes:
      - ./workspace:/workspace
    restart: unless-stopped
```

### Advantages

* Full autonomy for sophisticated use cases.
* Modular, composable deployment.
* Zero changes required to the MUXI SDK.
