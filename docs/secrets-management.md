# MUXI Secrets Management

## Overview

MUXI uses **encrypted secrets files** (`secrets.enc`) to keep sensitive configuration separate from formation config files. This allows formation files to be safely shared and version controlled while keeping API keys, tokens, and credentials secure.

> **Note:** Formation config files support three extensions (in priority order): `.afs` (Agent Formation Schema - preferred), `.yaml`, and `.yml`.

## Key Principles

1. **Keep YAML Files Safe**: Formation YAML files can be shared publicly since secrets are stored separately
2. **No Environment Variables**: MUXI does not read API keys from environment variables
3. **Encrypted Storage**: All secrets are stored in encrypted `secrets.enc` files using Fernet encryption
4. **Automatic Loading**: Secrets are automatically loaded when referenced in YAML using `${{ secrets.KEY_NAME }}`

## How It Works

### 1. Secrets File Structure

The `secrets.enc` file, when decrypted, contains a simple key-value store:

```
# Example decrypted content (DO NOT commit unencrypted!)
OPENAI_API_KEY=sk-...
ANTHROPIC_API_KEY=sk-ant-...
GEMINI_API_KEY=...
GITHUB_TOKEN=ghp_...
LINEAR_API_KEY=lin_api_...
MY_CUSTOM_SECRET=...
```

### 2. File Locations

Secrets files are placed **alongside the formation.afs**:

```
my-formation/
├── formation.afs      # Formation configuration (safe to share)
├── secrets.enc         # Encrypted secrets
└── .key               # Encryption key (NEVER commit to git!)

### 3. Using Secrets in formation.afs

Reference secrets in your formation YAML using the `${{ secrets.KEY_NAME }}` syntax:

```yaml
# formation.afs (or .yaml)
llm:
  models:
    - text: "openai/gpt-4o"
  api_keys:
    openai: "${{ secrets.OPENAI_API_KEY }}"
    anthropic: "${{ secrets.ANTHROPIC_API_KEY }}"

mcp:
  - id: github
    server: npx @modelcontextprotocol/server-github
    env:
      GITHUB_TOKEN: "${{ secrets.GITHUB_TOKEN }}"
```

When MUXI loads the formation:
1. Finds `secrets.enc` and `.key` in the formation directory
2. Decrypts the secrets file
3. Automatically replaces `${{ secrets.KEY_NAME }}` with the actual value
4. Values are never logged or exposed

### 4. Secret Manager API

```python
from muxi.services.secrets import SecretManager

# Initialize (happens automatically during formation load)
secret_manager = SecretManager()

# Load encrypted secrets from formation directory
secret_manager.load_secrets("path/to/formation/secrets.enc", "path/to/formation/.key")

# Access secrets in code (using the key names from the key-value store)
openai_key = secret_manager.get_secret("OPENAI_API_KEY")
github_token = secret_manager.get_secret("GITHUB_TOKEN")
```

## Security Best Practices

### Critical Rules

⚠️ **BACKUP YOUR `.key` FILE** - Store it securely outside the repository. If you lose it, you cannot decrypt your secrets! (though you can create a new secrets.enc file in a giffy if you have the original data)

⛔ **EXCLUDE `.key` FROM GIT** - Add `.key` to your `.gitignore` file immediately

### DO's ✅

1. **Use `${{ secrets.KEY_NAME }}` in YAML** - Keeps formation files shareable
2. **Backup `.key` file securely** - Store in password manager or secure location
3. **Use strong encryption keys** - Generated by the secrets service
4. **Commit only `secrets.enc`** - Encrypted files are safe to version control

### DON'Ts ❌

1. **Never commit `.key` files** - This would compromise all your secrets
2. **Never hardcode secrets in YAML** - Always use the `${{ secrets.KEY_NAME }}` syntax
3. **Never use environment variables** - MUXI uses only the secrets.enc file
4. **Never log secret values** - The system automatically masks them

## Common Issues and Solutions

### "Missing API key" errors

**Problem**: Formation can't find API keys
**Solution**: Ensure `secrets.enc` and `.key` exist in formation directory (or symlinked)

```bash
# Check if files exist
ls -la formation-dir/secrets.enc formation-dir/.key

# If missing, create symlinks to where you store your secrets.enc and .key files
ln -s ../../path/to/assets/secrets.enc formation-dir/secrets.enc
ln -s ../../path/to/assets/.key formation-dir/.key
```

### "Cannot decrypt secrets" errors

**Problem**: Wrong key or corrupted secrets file
**Solution**: Verify key matches the encrypted file

```bash
# Test decryption
python -m muxi.services.secrets decrypt \
  --input secrets.enc \
  --output test.txt \
  --key .key

# If it works, secrets are valid
rm test.txt
```

## Why Not Environment Variables?

### Formation YAML Files Stay Clean

By using `${{ secrets.KEY_NAME }}` syntax, your formation.afs files:
- Can be shared publicly without exposing secrets
- Can be version controlled safely
- Remain readable and maintainable
- Work across different environments with different secrets

### Security Benefits

1. **Encrypted at rest**: Secrets are always encrypted in `secrets.enc`
2. **Single source of truth**: One encrypted file instead of scattered env vars
3. **No accidental exposure**: Can't accidentally log or commit plain text secrets
4. **Easy rotation**: Update one file to change all secrets

## Quick Reference

### Example formation.afs using secrets:

```yaml
name: my-formation
version: "1.0"

llm:
  models:
    - text: "openai/gpt-4o"
  api_keys:
    openai: "${{ secrets.OPENAI_API_KEY }}"

mcp:
  - id: github-tools
    server: npx @modelcontextprotocol/server-github
    env:
      GITHUB_TOKEN: "${{ secrets.GITHUB_TOKEN }}"

agents:
  - id: assistant
    name: Assistant
    model: openai/gpt-4o
    instructions: "You are a helpful assistant."
```

### Verify your setup:

```bash
# Check files exist
ls -la formation.afs secrets.enc .key

# .key should have restricted permissions
# -rw------- (600) is ideal
```

## Summary

- **Purpose**: Keep formation.afs files safe to share by separating secrets
- **Usage**: Reference secrets with `${{ secrets.KEY_NAME }}` in YAML
- **Storage**: Secrets are encrypted in `secrets.enc` alongside formation.afs
- **Security**: NEVER commit `.key` files - back them up securely
- **No env vars**: MUXI ignores environment variables for secrets

This keeps your formation files shareable while your secrets remain secure!
