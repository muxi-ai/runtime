## Technical Architecture

### Hybrid Knowledge System:
```
Formation Config
    ↓
FileKnowledge Sources
    ↓
DocumentChunkManager (chunking)
    ↓
LLM Embeddings API
    ↓
┌─────────────────┐     ┌──────────────────┐
│  Disk Cache     │ ←→  │ ShortTermMemory  │
│ (JSON files)    │     │    (FAISS)       │
└─────────────────┘     └──────────────────┘
```

### Cache Structure:
```
~/.muxi/{formation_id}/
└── cache/
    └── knowledge/
        ├── {md5_hash1}.cache
        ├── {md5_hash2}.cache
        └── ...
```

### Metadata Tracking:
```json
{
  "source": "/absolute/path/to/file.md",
  "source_type": "FileKnowledge", 
  "content_hash": "md5_of_file_content",
  "chunk_index": 0,
  "total_chunks": 5,
  "processing_method": "markitdown",
  "file_extension": ".md"
}
```

## Performance Metrics

### Before Optimization:
- Every formation restart regenerated ALL embeddings
- Cost: ~$0.10-0.50 per restart (depending on knowledge size)
- Time: 30-60 seconds for full regeneration

### After Optimization:
- Only changed files regenerate embeddings
- Cost: $0 for unchanged knowledge, minimal for changes
- Time: <5 seconds for cache loading
- Example: 2 files with 197 chunks → instant load from cache
