## Key Features Validated

### 1. Credential Modes

#### Redirect Mode (Enterprise)
- **Purpose**: External credential management for compliance
- **Behavior**: Shows configured message, no inline collection
- **Tests**: 8E1a, 8E1b, 8E1c
- **Example Response**: "Please configure your API credentials in the external credential manager"

#### Dynamic Mode (Developer)
- **Purpose**: Inline credential collection for convenience
- **Behavior**: Prompts for credentials in chat
- **Requirements**: Service must have `accept_inline: true`
- **Tests**: 8E2, 8E2a, 8E2b, 8E2c

### 2. Multiple Account Support

**Tested Scenarios**:
- User has 0 credentials → Prompts for new
- User has 1 credential → Uses directly
- User has 2+ credentials → Triggers selection
- User wants different account → Allows addition

**Key Achievement**: Fixed SQLAlchemy error preventing multiple credentials per service

### 3. Duplicate Token Detection

**Implementation** (August 30, 2025):
```python
async def check_duplicate(user_id, service, credentials):
    # Fetch all existing credentials
    existing = await fetch_credentials(user_id, service)
    
    # Decrypt and compare each
    for cred in existing:
        decrypted = decrypt(cred)
        if decrypted == credentials:
            return True  # Duplicate found
    
    return False
```

**Benefits**:
- Prevents storing same token multiple times
- Saves unnecessary validation API calls
- User-friendly message: "That token is already stored. You're all set!"

### 4. Retry Loop Handling

**Flow Tested**:
1. User provides invalid token
2. System validates and rejects
3. Prompts for retry (up to 3 attempts)
4. User can provide new token or cancel

**Test Coverage**:
- Single retry success (8E4, 8E8)
- Double retry success (8E5, 8E9)
- User cancellation (8E6, 8E10)

### 5. Security Features

#### Encryption
- Per-user key derivation using PBKDF2
- Fernet encryption for storage
- Zero-configuration (uses formation_id)

#### Redaction
- Credentials never appear in logs
- Token patterns detected and masked
- Error messages sanitized

#### Isolation
- User credentials strictly isolated
- No cross-user access possible
- Session-based state management

## Critical Bug Fixes

### 1. Multiple Credentials Support (Aug 30)
**Issue**: SQLAlchemy error "Multiple rows were found when one or none was required"
**Fix**: Changed `.scalar_one_or_none()` to `.scalars().all()`
**Impact**: Users can now have unlimited accounts per service

### 2. Duplicate Detection (Aug 30)
**Issue**: Same token could be stored multiple times
**Fix**: Added `check_duplicate()` before validation
**Impact**: Prevents duplicate storage and saves API calls

### 3. Clarification Flow Separation (Aug 30)
**Issue**: Credential requests going through clarification
**Fix**: Proper separation of flows after "I need a different account"
**Impact**: Clean credential collection without clarification interference

## Best Practices Established

1. **Always Check Duplicates First**: Before validation to save API calls
2. **Decrypt for Comparison**: Compare actual values, not encrypted
3. **Use Identity Discovery**: Store meaningful names, not generic service names
4. **Separate Concerns**: Credential flow distinct from clarification
5. **Fail Gracefully**: User-friendly messages for all error cases
