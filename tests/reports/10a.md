## Implementation Details

### Architecture Changes

#### 1. Separated Generator Logic
```python
async def _create_stream_generator(...) -> AsyncGenerator[str, None]:
    """Generator function with yield"""
    asyncio.create_task(delayed_process())
    async for event in self._stream_request(...):
        yield event

async def chat(...):
    """Regular async function with return"""
    if use_streaming:
        return self._create_stream_generator(...)
    else:
        return await self._process_sync_chat(...)
```

#### 2. Fire-and-Forget with Delay
```python
async def delayed_process():
    await asyncio.sleep(1.0)  # Ensure subscription ready
    streaming_manager.emit_event(request_id, "progress", "Starting...")
    result = await self._process_sync_chat(...)
    streaming_manager.emit_event(request_id, "complete", "Done")
    streaming_manager.disable_streaming(request_id)  # Clean termination
```

#### 3. Event Format
```python
{
    'request_id': 'req_xxx',
    'user_id': 'test_user',
    'session_id': 'test_session',
    'type': 'progress',  # or 'complete', 'thinking', etc.
    'content': 'Event message',
    'timestamp': 1234567890.123,
    'stage': 'init',  # Optional metadata
}
```

## Technical Notes

### Critical Timing Issue
The 1-second delay in `delayed_process()` is essential. Without it:
- Events may be emitted before subscription is established
- Early events would be lost
- Test would hang waiting for events that already passed

### Subscription Loop Termination
The `streaming_manager.disable_streaming(request_id)` call is critical:
- Removes the event stream from manager
- Causes subscription loop to exit (`while request_id in self.event_streams`)
- Prevents indefinite hanging of async generators

### Context Propagation
Originally attempted to pass observability context to fire-and-forget task:
- Not currently needed with manual event emission
