## Issues Identified and Resolved

### 1. Observability Migration
**Problem**: Logger/logging usage needed to be replaced with observability events across multiple files.

**Files Modified**:
- `src/muxi/formation/agents/agent.py` - 3 logger calls replaced
- `src/muxi/services/a2a/client.py` - 11 logger calls replaced
- `src/muxi/services/mcp/service.py` - Debug comments cleaned up

**Resolution**: Successfully migrated all logging to observability events.

### 2. Missing Observability Events
**Problem**: Several observability event types were being used but not defined, causing "local variable 'observability' referenced before assignment" errors.

**Missing Events Added**:
```python
AGENT_PROCESSING_ERROR = "agent.processing.error"
A2A_MESSAGE_PROCESSED = "a2a.message.processed"
A2A_TASK_HANDOFF = "a2a.task.handoff"
AGENT_A2A = "agent.a2a"
AGENT_A2A_MESSAGE_RECEIVED = "agent.a2a.message.received"
```

**File Modified**: `src/muxi/datatypes/observability.py`

### 3. Duplicate Import Issue
**Problem**: Function-level imports of observability in `a2a/client.py` were creating scope conflicts.

**Resolution**: Removed duplicate local imports at lines 206 and 236, keeping only the module-level import.

### 4. Workflow Decomposition Issues

#### 4.1 Incorrect Task Routing
**Problem**: "Gather system usage information" tasks were incorrectly routed to `web_research` capability instead of `system_administration`.

**Root Cause**: The workflow decomposer didn't have proper context about what each agent's capabilities actually meant.

**Resolution**: Improved capability descriptions in the decomposer to clarify:
- `web_research` → "Web searches, online information gathering, internet research"
- `system_administration` → "System monitoring (CPU, memory, disk), resource usage, diagnostics"

#### 4.2 Unnecessary Intermediate Steps
**Problem**: The LLM was adding unnecessary "write description" tasks between data gathering and issue creation.

**Example of Bad Workflow**:
1. Gather system metrics
2. Write description of metrics ← UNNECESSARY
3. Create Linear issue

**Resolution**: Enhanced the decomposition prompt to:
- Emphasize MINIMAL workflows
- Clarify that writing tasks are only for substantial documents
- Add explicit examples of good vs bad workflows
- Specify that platform agents can format data themselves

**Files Modified**:
- `src/muxi/formation/workflow/decomposition_prompt.md`
- `src/muxi/formation/workflow/decomposer.py`

### 5. Hardcoded Capability Checks
**Problem**: The decomposer had hardcoded checks for specific capabilities (linear, jira, github, etc.), making it non-scalable.

**Resolution**: Replaced hardcoded checks with a generic approach that:
- Uses agent descriptions if available
- Falls back to generic descriptions based on capabilities
- Works with any new agents/capabilities without code changes
