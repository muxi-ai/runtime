## 🎯 Zero-Risk Implementation Strategy

### Key Safety Guarantees

1. **Optional Field with Default**: `topics: List[str] = Field(default_factory=list)` means:
   - All existing code works without modification
   - Pydantic automatically provides `[]` if not specified
   - No field validators on topics (unlike required_capabilities/acceptance_criteria)

2. **No Logic Dependencies**: Verified that NO existing code checks for topics:
   - Workflow decomposition uses: `complexity_score`, `implicit_subtasks`, `required_capabilities`
   - Time estimator uses: `complexity_score`, `requires_decomposition`
   - Approval logic uses: `is_explicit_approval_request`, `complexity_score`
   - SOP detection uses: `explicit_sop_request`
   - **Topics are purely additive metadata**

3. **Fallback Safety**: All fallback paths return `topics=[]`:
   - Heuristic analysis (no LLM)
   - LLM errors/exceptions
   - Custom complexity functions
   - Hybrid mode when LLM unavailable

```python
# Normalize explicit_sop_request: strip whitespace and convert empty/whitespace to None
explicit_sop = data.get("explicit_sop_request")
if explicit_sop:
    explicit_sop = explicit_sop.strip()
    if not explicit_sop:  # Empty after stripping
        explicit_sop = None

# NEW: Extract and normalize topics
topics = data.get("topics", [])
if not isinstance(topics, list):
    topics = []  # Handle malformed response
# Normalize: strip whitespace, lowercase, remove empty strings
topics = [str(t).strip().lower() for t in topics if t]
topics = [t for t in topics if t][:5]  # Remove empties, limit to 5

return RequestAnalysis(
    complexity_score=float(data.get("complexity_score", 5.0)),
    requires_decomposition=False,
    requires_approval=False,
    implicit_subtasks=data.get("implicit_subtasks", []),
    required_capabilities=data.get("required_capabilities", ["general"]),
    acceptance_criteria=data.get("acceptance_criteria", []),
    confidence_score=float(data.get("confidence_score", 0.8)),
    is_scheduling_request=data.get("is_scheduling_request", False),
    is_explicit_approval_request=data.get("is_explicit_approval_request", False),
    explicit_sop_request=explicit_sop,
    topics=topics,  # NEW
)
```

**Why safe**:
- Defensive: checks `isinstance(topics, list)`, handles malformed data
- Falls back to `[]` on any error
- Normalization prevents issues: lowercase, strip whitespace, limit length
- Existing try/except wraps this - errors return fallback with `topics=[]`

### 5. Update Hybrid Method to Use LLM Topics

**File**: `src/muxi/formation/workflow/analyzer.py`
**Location**: In `_hybrid_analyze_request()` method (after line 473)

```python
if self.llm:
    try:
        llm_analysis = await self._llm_analyze_request(user_message, context)
        llm_score = llm_analysis.complexity_score

        # Merge capabilities and subtasks
        combined_capabilities = list(
            set(
                heuristic_analysis.required_capabilities
                + llm_analysis.required_capabilities
            )
        )
        combined_subtasks = list(
            set(heuristic_analysis.implicit_subtasks + llm_analysis.implicit_subtasks)
        )

        heuristic_analysis.required_capabilities = combined_capabilities
        heuristic_analysis.implicit_subtasks = combined_subtasks
        heuristic_analysis.topics = llm_analysis.topics  # NEW: Use LLM topics
    except Exception:
        # Use heuristic score if LLM fails
        pass  # heuristic_analysis.topics remains []
```

**Why safe**:
- Only updates topics if LLM succeeds
- If exception, topics stays `[]` from heuristic
- Mutating existing object pattern matches other fields
